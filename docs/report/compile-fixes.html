Claims that contradict each other or the actual chatbot

These matter most if the lecturer opens the bot during marking. Each was checked against the live chatbot.

  1. High§1.1 vs §3.3

    The report gives two different lists of IT domains.

    §1.1 says Software Engineering, Data Science, Cybersecurity, Systems & Networking. §3.3 says networking, cybersecurity, cloud, web development, data/AI, devops. The second list is what the chatbot actually uses.

    Change §1.1 to match §3.3.
  2. High§1.4

    The report overview describes sections that do not exist.

    §1.4 promises System Architecture & Design, Implementation & Technology Stack, Evaluation & Results and Conclusion & Future Work. The report actually contains Literature Review, Methodology, Implementation and Conclusion.

    Rewrite the §1.4 paragraph to list the real sections.
  3. High§1.3

    The report claims the chatbot is embedded in a website. It is not.

    §1.3 claims Seamless Web Integration with embedded deployment via standard web chat standards. The chatbot exists only as a Botpress shareable link and is not embedded anywhere.

    Either embed it and keep the claim, or reword to describe it honestly as a hosted web chat widget accessed by link.
  4. High§1.1, §1.3

    "Curated educational resources" is claimed, but the bot gives no links.

    §1.1 promises curated educational resources and §1.3 lists Resource Curation as a key feature. In testing the chatbot returned zero URLs — it now says things like "search for a CompTIA Network+ free course" instead of linking anywhere.

    Best fix is to add a verified link list to the Knowledge Base. Otherwise soften the claim. Section 5 already raises this under Future Work, so it will not look like an oversight.
  5. Medium§4

    "Clarification Before Answering" is no longer accurate.

    §4 states the bot consistently prompted for a domain before providing detailed information. Since the recent update it answers general questions directly — "Explain what a subnet is" now gets a straight answer with no clarifying question.

    Reword to say it asks which area the learner wants before generating a personalised roadmap, which is still true.
  6. Medium§4 vs §3.3

    Two different mechanisms are described for the same thing.

    §4 says the team expanded NLU training data and added utterances to Botpress's Intent library. But §3.3 and §3.6 say classification is done by GPT-4.1 in AI Task nodes. These are different approaches, and a marker who knows Botpress will notice.

    Describe whichever was actually built, and remove the other.
  7. MediumTable 1

    The rule table has two gaps worth acknowledging.

    R5 (web development) has no userLevel condition, so it fires for advanced learners too. And R1–R4 are all userLevel = beginner, meaning no rule in the table handles intermediate or advanced users at all.

    No change needed to the table — Section 5 already raises both as Future Work, which reads as awareness rather than an error. Just do not claim elsewhere that the rules adapt to skill level.
  8. Low§2.1, §2.3

    The Thottoli finding is slightly overstated.

    Thottoli et al. found the research literature fragmented across disciplines. §2.3 turns this into a claim about systems lacking a consistent architecture to build that behavior on. If the marker reads the source, that is arguably a misreading.

    Keep the point but attribute it accurately — the literature is fragmented, and the project responds by adopting an explicit rule structure.
